# Spec Delta

## Purpose

让平台 CLI 在容器环境里可安装、可升级、可多版本共存，并把「装好了」「凭据对」「平台通」三件事变成后台可见的事实，而不是等到发布时才暴露的运行时意外。

## ADDED Requirements

### Requirement: CLI 安装到持久卷
CLI MUST 安装到跨容器重建仍然存在的持久卷内，MUST NOT 只存在于容器可写层；每个 CLI 版本 MUST 拥有独立安装目录，并以一个可切换的当前版本指向。

#### Scenario: 容器重建
- **WHEN** 容器被重建后启动
- **THEN** 已安装的 CLI 仍然可用，当前版本指向保持不变

#### Scenario: 版本回退
- **WHEN** 升级后的 CLI 探测失败
- **THEN** 用户可以切换回上一个已安装版本，无需重新下载安装

### Requirement: 安装是长任务
CLI 安装与升级 MUST 作为可观察的长任务执行，记录进度、输出与结果，MUST 有超时；安装失败 MUST NOT 破坏此前可用的版本。

#### Scenario: 安装耗时较长
- **WHEN** 用户在后台触发安装
- **THEN** 安装以任务形式执行，界面可查看进度与日志，且不阻塞其他操作

#### Scenario: 安装失败
- **WHEN** 安装过程因网络或依赖问题失败
- **THEN** 任务记录失败原因，当前版本指向保持原状

### Requirement: 三层可用性探测
CLI 可用性 MUST 分三层报告：安装完好、凭据可用、平台可达；三层结果 MUST 独立显示，且平台可达层 MUST 能区分配置错误与网络或来源限制问题。

#### Scenario: 密钥有效但出口 IP 未白名单
- **WHEN** 凭据有效但平台因来源 IP 拒绝请求
- **THEN** 探测结果明确指出是来源限制，而不是笼统的不可用

### Requirement: 无法自动安装的类型显式标注
对于不能由后台自动安装的 CLI，系统 MUST 将其标注为需人工安装并给出安装指引，MUST NOT 提供注定失败的安装按钮。

#### Scenario: 仅提供桌面安装包的平台
- **WHEN** 某个平台的 CLI 只能通过桌面安装包获得
- **THEN** 该类型在后台显示为需人工安装并提供指引，探测仍可给出结果

### Requirement: 首次启动预置
系统 SHALL 支持一份预置清单，在 CLI 卷为空时自动安装清单内声明的版本，使首次启动即可用，同时保留后续在界面内升级的能力。

#### Scenario: 首次启动
- **WHEN** 容器首次启动且 CLI 卷为空
- **THEN** 系统按预置清单安装所需版本并报告结果
