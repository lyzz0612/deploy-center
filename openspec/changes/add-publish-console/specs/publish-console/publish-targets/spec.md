# Spec Delta

## Purpose

把「怎么发布」固化在可插拔的目标类型里，把「发到哪」降级为可增删的实例数据，使新增小游戏平台或新增一种 H5 部署方式只需要新增一个插件，而不改动核心发布流程。

## ADDED Requirements

### Requirement: 目标类型注册表
每个发布目标类型 MUST 通过注册声明：唯一标识、可接受的包类型、所需凭据类型、是否具备即时回滚能力、声明支持的阶段与能力。新增一个目标类型 MUST 只新增注册项与插件实现，不改动核心发布流程。

#### Scenario: 类型声明决定可选目标
- **WHEN** 用户为一个微信包选择发布目标
- **THEN** 系统只列出声明接受微信包的目标类型下的实例

#### Scenario: 新增目标类型
- **WHEN** 开发者新增一个目标类型插件并完成注册
- **THEN** 该类型出现在设置页并可创建实例，核心发布流程无需改动

### Requirement: 目标实例作为游戏级数据
发布目标实例 SHALL 属于某个游戏，由目标类型、凭据引用与位置字段组成；同一目标类型 SHOULD 允许存在多个实例。

#### Scenario: 同一平台多个实例
- **WHEN** 用户为同一款游戏添加两个微信目标实例，分别使用不同 appid 与不同凭据
- **THEN** 两个实例独立存在，发布其中一个不影响另一个

#### Scenario: 同一存储不同路径
- **WHEN** 用户添加两个共用同一凭据但路径前缀不同的 H5 目标
- **THEN** 两个实例可各自接收发布，互不覆盖

### Requirement: 包类型兼容性校验
系统 MUST 在发布入口处校验包类型被目标类型接受；不兼容的组合 MUST 无法发起发布。

#### Scenario: 跨类型发布
- **WHEN** 用户尝试把一个 H5 包发到只接受微信包的目标
- **THEN** 系统阻止该操作并说明该目标不接受此包类型

### Requirement: 环境检测分两级
环境检测 MUST 分为类型级（同类型实例共享，如 CLI 是否可用）与实例级（每个实例独立，如凭据是否有效、平台是否可达）两层；类型级检测 MUST NOT 针对每个实例重复执行。

#### Scenario: 同一类型多个实例
- **WHEN** 一款游戏有多个同类型目标实例
- **THEN** CLI 状态在类型级显示一次，各实例只显示自身的凭据与连通性结果

### Requirement: 目标实例去重与删除
系统 SHALL 在保存目标实例时校验同一游戏内（同类型、同凭据、同位置字段）不重复；没有发布记录引用的目标 SHALL 可以被直接删除，被引用的目标 MUST NOT 被删除。系统 MUST NOT 提供归档这一中间状态。

#### Scenario: 重复目标
- **WHEN** 用户保存一个与已有实例凭据和位置完全相同的目标
- **THEN** 系统拒绝保存并指出冲突的实例

#### Scenario: 删除有发布历史的目标
- **WHEN** 用户尝试删除一个有历史发布记录的目标
- **THEN** 系统拒绝删除，并提供「清除该目标已结束的发布记录」这一前置操作

#### Scenario: 清掉历史后删除目标
- **WHEN** 用户清除某目标的全部已结束发布记录后再删该目标
- **THEN** 删除成功，该目标不再出现在任何列表里

#### Scenario: 删除没有发布历史的目标
- **WHEN** 用户删除一个从未发布过的目标
- **THEN** 删除成功
