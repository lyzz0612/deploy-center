# Spec Delta

## Purpose

让 CI 在构建完成后只登记产物元数据而不传输文件内容，把带宽与存储 I/O 留在外部，同时保证后台对每个版本的来源、完整性与可用性都有明确记录。

## ADDED Requirements

### Requirement: 上报接口鉴权
上报接口 MUST 要求有效的 CI key 才能写入；缺少或错误的 key MUST 返回 401 且不产生任何副作用。

#### Scenario: 无 key 上报
- **WHEN** 请求未携带有效 CI key
- **THEN** 系统返回 401 并拒绝写入

### Requirement: 产物地址由 CI 提供
上报内容 MUST 包含公开可访问的产物 URL，以及包类型、构建标识、大小、sha256 与可选 commit、描述。后台 MUST NOT 要求持有读取外部存储的凭据。

#### Scenario: 上报构建
- **WHEN** CI 上报游戏、包类型、构建标识、产物 URL、大小与 sha256
- **THEN** 系统登记一条可读的构建记录，等待被选择发布

#### Scenario: 缺少校验信息
- **WHEN** 上报内容缺少 sha256 或大小
- **THEN** 系统返回 400 并拒绝登记

### Requirement: 上报幂等
同一游戏、同一包类型、同一构建标识的重复上报 MUST 更新既有记录而不是产生重复条目。

#### Scenario: CI 重跑
- **WHEN** CI 用相同的游戏、包类型与构建标识再次上报
- **THEN** 系统更新该构建记录，构建总数不变

### Requirement: 发布前校验产物可用性
执行发布任务前，后台 MUST 下载产物并校验大小与 sha256；下载失败 MUST 区分「地址不可达」「无权限」「超时」并记录当时使用的 URL。

#### Scenario: 产物链接已过期
- **WHEN** 发布时产物地址返回 404
- **THEN** 任务失败，日志明确记录地址不可达与使用的 URL，不重试同一死链

#### Scenario: 摘要不一致
- **WHEN** 下载到的产物 sha256 与上报值不一致
- **THEN** 任务失败并标记为完整性校验失败，不把产物交给插件

### Requirement: 构建视图
构建列表 SHALL 支持按游戏与包类型筛选，并 SHALL 能按 commit 聚合展示同一次构建产出的多个包；每个包 MUST 显示其在各发布目标上的最新发布状态摘要。

#### Scenario: 查看一次构建的全貌
- **WHEN** 用户打开构建列表
- **THEN** 同一 commit 的微信、抖音、H5 三个包聚合为一行，行内显示各目标的最新状态
