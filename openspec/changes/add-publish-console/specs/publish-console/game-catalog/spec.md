# Spec Delta

## Purpose

维护多款小游戏的登记册与包类型清单，为构建上报和发布目标选择提供稳定的分类依据，并保证分类发生变化时不产生悬空引用。

## ADDED Requirements

### Requirement: 游戏登记册
后台 SHALL 维护一份小游戏登记册，每款游戏有不可变的 slug 作为唯一标识，以及可修改的显示名与状态（启用 / 归档）。slug 创建后 MUST 不可更改，因为它会出现在构建上报、发布目标与产物路径中。

#### Scenario: 创建游戏
- **WHEN** 用户创建游戏并填写 slug "demo" 与显示名
- **THEN** 系统保存该游戏，并允许后续以 slug "demo" 绑定构建上报与发布目标

#### Scenario: slug 重复
- **WHEN** 用户创建游戏时使用了已存在的 slug
- **THEN** 系统拒绝创建并明确指出该 slug 已被占用

#### Scenario: 归档游戏
- **WHEN** 用户把某游戏归档
- **THEN** 该游戏不再接受新的构建上报与发布，历史记录保持可读

### Requirement: 包类型作为数据维护
包类型 SHALL 是后台可增删改的数据记录，除唯一标识与显示名外不携带任何影响系统处理产物的行为字段。新增一个包类型 MUST 不需要改代码。

#### Scenario: 新增包类型
- **WHEN** 用户在后台新增包类型 "qq"
- **THEN** 该类型立即出现在包类型列表中，并可被构建上报引用

#### Scenario: 无发布目标支持的包类型
- **WHEN** 某个包类型没有任何发布目标类型声明接受它
- **THEN** 后台在包类型列表中显式提示该类型当前无法发布

### Requirement: 包类型引用保护
被任一构建记录引用的包类型 MUST NOT 被物理删除，只允许归档。

#### Scenario: 删除被引用的包类型
- **WHEN** 用户尝试删除一个已被构建上报引用过的包类型
- **THEN** 系统拒绝删除，并说明存在引用的构建记录

### Requirement: 未登记包类型拒绝写入
系统 MUST NOT 创建指向未登记包类型的构建记录。

#### Scenario: 上报未登记包类型
- **WHEN** CI 上报的包类型在后台不存在
- **THEN** 系统返回 400 并说明该包类型未登记，不写入任何记录
