# Spec Delta

## Purpose

把一次发布变成有明确起点、可追踪阶段、失败可重试、结果可验证、并能按目标能力回滚的历史记录，使多平台发布不依赖人的记忆和手工核对。

## ADDED Requirements

### Requirement: 发布记录
每次发布 MUST 产生一条独立的发布记录，维度为「构建 × 目标」。记录中的目标、参数与发起时间 MUST 不可变，状态与日志可追加。

#### Scenario: 同一构建多次发布
- **WHEN** 用户把同一构建先后发布到两个目标
- **THEN** 系统产生两条独立记录，各自的参数与结果互不影响

### Requirement: 多阶段执行
发布 MUST 按目标类型声明的阶段顺序执行，并逐阶段记录状态与日志；只声明一个阶段的目标类型 MUST 同样按该流程执行。

#### Scenario: 单阶段发布
- **WHEN** 目标类型只声明上传阶段
- **THEN** 发布记录只包含上传阶段及其结果

#### Scenario: 多阶段发布
- **WHEN** 目标类型声明了上传与提审两个阶段
- **THEN** 记录分别显示两个阶段的状态，前一阶段失败时后续阶段不执行

### Requirement: 失败只重试失败阶段
重试 MUST 从第一个未成功的阶段继续，已成功的阶段 MUST NOT 重新执行。

#### Scenario: 提审阶段失败后重试
- **WHEN** 上传阶段成功、提审阶段失败后用户点击重试
- **THEN** 系统只重新执行提审阶段，并保留一次新的尝试记录

### Requirement: 发布前检查
系统 MUST 在允许发起发布前完成与该目标相关的前置检查（产物可取、凭据可用、CLI 可用、目标可写）；任一检查未通过 MUST 阻止发起并指出未通过的项。

#### Scenario: CLI 不可用
- **WHEN** 目标所需的 CLI 未安装
- **THEN** 发布入口不可用，并提示先完成安装

### Requirement: 结果验证
目标类型声明支持验证时，发布完成 MUST 执行验证并把结论写入记录；验证不通过 MUST 使记录不进入成功状态。

#### Scenario: 指针切换后验证
- **WHEN** H5 目标完成生效指针覆盖并声明支持验证
- **THEN** 后台按该类型的方式回读生效状态，验证不通过则记录标记为失败

### Requirement: 回滚按目标能力执行
回滚方式 MUST 由目标类型声明的能力决定：声明为「重新发布」时 MUST 以旧版本构建发起一次新发布；声明为「指针回退」时 MUST 只改变生效指针而不重新写入产物；声明为「不支持」时 MUST 不提供回滚入口。

#### Scenario: 指针回退
- **WHEN** 用户对支持指针回退的目标执行回滚
- **THEN** 生效指针回到上一版本，且不产生新的产物写入

#### Scenario: 不支持回滚
- **WHEN** 目标类型声明不支持回滚
- **THEN** 该目标的发布记录上不显示回滚入口

### Requirement: 发布状态机
发布记录的状态 MUST 限定为排队中、执行中、成功、失败、超时、已取消，且只允许从排队中或执行中转移到终止状态。

#### Scenario: 超时
- **WHEN** 某阶段执行超过该类型声明的超时时间
- **THEN** 记录进入超时状态，日志保留已产生的输出
